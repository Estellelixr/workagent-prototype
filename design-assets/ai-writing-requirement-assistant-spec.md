# AI 辅助生成写作要求 - 研发交付版（组合说明）

> 若任务代码需要为每个按钮直接配置一段完整提示词，请优先使用 `ai-requirement-assistant-task-prompts.md`；本文件保留字段和交互说明。

适用功能：

- AI 写作基础信息页的「写作要求 > AI生成」
- AI 仿写填写要求页的「仿写要求 > AI辅助生成」

任务目标：根据用户**当前已填写或已确认**的信息，生成一段可直接回填到要求输入框的建议。它不是正文/大纲生成任务，不得输出完整文章。

> `ai-writing-task-prompts.md` 是后续“生成正文/大纲”节点的提示词；本文件才是这两个 AI 辅助按钮应接入的提示词。

## 1. 统一约束

### 系统提示词（所有模式共用）

```text
你是“写作要求辅助生成器”。你的唯一任务是根据当前已提供的信息，生成一段供用户编辑的写作要求，而不是生成文章、大纲、结语或仿写正文。

严格遵守：
1. 只使用输入中已有的信息和可由文种/场景自然推断出的通用写作方法；不得虚构单位、人员、时间、地点、数据、政策依据、职责分工或具体事项。
2. 没有输入的字段不要猜测，也不要写“请补充单位/时间”等占位提示。
3. 输出需贴合当前写作模式、文种和具体场景，不能机械固定为“背景、任务、责任、时限”等万能结构；例如新闻、讲话、函、纪要、总结、书信应采用各自适配的关注点。
4. 表述应可执行、可编辑，重点包含合适的结构、内容重点、语气和边界；避免“结构完整、语言正式”等空泛重复话。
5. 不复述全部输入，不解释推理过程，不使用 Markdown、标题、编号或项目符号。
6. 只输出一段中文：AI 写作 60 至 140 字；AI 仿写 100 至 220 字。
```

### 调用建议

- `temperature: 0.25`
- `maxTokens: 320`（AI 仿写可为 `480`）
- 不开启深度思考
- 只有标题为空时，生成全文/生成大纲按钮禁用；其他模式按页面既有必填校验执行。
- 直接将输出回填文本框，保留用户二次编辑；不要覆盖用户已编辑的内容，建议点击时先二次确认或追加覆盖确认。

## 2. 原型实际字段与传参矩阵

| 功能 | 页面实际可用字段 | 不应假定存在的字段 |
| --- | --- | --- |
| 生成全文 | `writingMode`、`documentCategory`、`sceneName`、`title`、`wordCount`、`draftingUnit` | 原文、参考素材、已生成大纲 |
| 生成大纲 | `writingMode`、`documentCategory`、`sceneName`、`title`、`wordCount`、`draftingUnit` | 原文、参考素材、已生成大纲 |
| 大纲成文 | `writingMode`、`title`、`sourceContent`（用户上传/粘贴的大纲）、`wordCount`、`draftingUnit` | 场景、参考素材 |
| 继续写 | `writingMode`、`sourceContent`（用户上传/粘贴的正文）、`wordCount` | 标题、场景、拟文单位 |
| 生成结语 | `writingMode`、`sourceContent`（用户上传/粘贴的正文） | 标题、场景、字数、拟文单位 |
| AI 仿写 | `title`、`docType`、`keywords[]`、`directions[]`、`tones[]`、`structureItems[]`、`contentLength`、`draftingUnit` | 固定“规范用语”字段；该字段已从界面要求中移除 |

### 通用请求体

```json
{
  "task": "writing_requirement_assistant",
  "mode": "生成全文",
  "title": "（单位/部门名称）关于举办XXX比赛的通知",
  "documentCategory": "通知",
  "sceneName": "举办比赛通知",
  "wordCount": 1500,
  "draftingUnit": "",
  "sourceContent": "",
  "copyAnalysis": null
}
```

字段处理规则：

1. 未填写的字符串、空数组、`null` 字段不拼入用户提示词。
2. `sourceContent` 用于理解上下文即可，建议去除附件头尾、连续空行后最多传 4,000 字；若超出，保留开头 2,000 字和结尾 2,000 字。
3. 仿写使用的 `copyAnalysis` 必须取“结构提取页用户编辑后的最终值”，不取初次 AI 提取的旧值。
4. 每个 `structureItems` 均需传递 `title`、`writingFunction`、`pattern`、`skeleton`；这些字段即使当前在“查看解析”中收起，也会参与仿写要求生成。

## 3. AI 写作 - 生成全文

### 用户提示词模板

```text
当前写作模式：生成全文
一级文种：{{documentCategory}}
具体场景：{{sceneName}}
公文标题：{{title}}
目标字数：{{wordCount}}
拟文单位：{{draftingUnit}}

请据此生成“写作要求”。重点应随文种和场景变化：明确适合的正文组织方式、应写清的关键信息、受众口径和语言风格。不要生成全文。
```

### 预期回填示例

```text
采用比赛通知的正式口径，交代活动目的、参赛范围、比赛安排、报名方式和注意事项；时间、地点及奖项以已确认信息为准，语言简明清晰，便于各单位执行。
```

## 4. AI 写作 - 生成大纲

### 用户提示词模板

```text
当前写作模式：生成大纲
一级文种：{{documentCategory}}
具体场景：{{sceneName}}
公文标题：{{title}}
目标字数：{{wordCount}}
拟文单位：{{draftingUnit}}

请据此生成“写作要求”。要求应服务于后续先出大纲：说明大纲宜采用的层级和应覆盖的关键信息，且要贴合当前文种与场景。不要直接输出大纲。
```

### 预期回填示例

```text
先形成会议通知的结构化大纲，按会议目的、时间地点、参会范围、议程安排和会务要求组织要点；层级简洁，便于后续补入具体事项并扩写成正式通知。
```

## 5. AI 写作 - 大纲成文

### 用户提示词模板

```text
当前写作模式：大纲成文
公文标题：{{title}}
目标字数：{{wordCount}}
拟文单位：{{draftingUnit}}
已有大纲：
{{sourceContent}}

请据此生成“写作要求”。要求应强调严格遵循已有大纲的层级、顺序和重点，将提纲要点自然扩写为连贯正文；只补全表达，不擅自改变大纲主题或新增无关章节。不要输出正文。
```

### 预期回填示例

```text
严格沿用现有提纲的章节顺序和重点，将各要点扩写为连贯正式的段落；一级标题下重点写清措施和落实路径，不新增提纲之外的事项，整体篇幅控制在目标字数附近。
```

## 6. AI 写作 - 继续写

### 用户提示词模板

```text
当前写作模式：继续写
目标字数：{{wordCount}}
已有正文：
{{sourceContent}}

请据此生成“写作要求”。要求应说明如何从上文自然承接，保持已有文本的文体、语气、层级、视角和编号体系；避免复述已写内容，也不要擅自改变原有立场或事实。不要输出续写正文。
```

### 预期回填示例

```text
从现有正文的最后一部分自然承接，保持通知类文本的正式语气和既有编号体系，续写尚未展开的执行要求或保障安排，避免重复前文已明确的背景和任务。
```

## 7. AI 写作 - 生成结语

### 用户提示词模板

```text
当前写作模式：生成结语
已有正文：
{{sourceContent}}

请据此生成“写作要求”。要求应说明结语如何承接上文的文体、语气和收束方式；应简洁有力，不重复全文，不引入新任务、新事实或未出现的时间要求。不要输出结语正文。
```

### 预期回填示例

```text
结语延续正文的正式部署口径，简要强调贯彻落实和协同推进，形成自然收束；不重复前文任务，不新增具体时限、责任单位或落款信息。
```

## 8. AI 仿写 - 仿写要求

### 仿写分析数据结构

```json
{
  "title": "关于开展二季度安全生产检查工作的通知",
  "docType": "通知",
  "keywords": ["责任分工", "任务闭环", "时限反馈", "督导问效"],
  "directions": ["下行"],
  "tones": ["正式稳妥", "工作化"],
  "structureItems": [
    {
      "title": "统一思想认识，明确总体要求",
      "writingFunction": "政治站位定调，说明任务背景和总体要求",
      "pattern": "总分总，先定调再提出整体要求",
      "skeleton": "为深入贯彻[上级部署/核心目标]，现就[工作事项]提出如下要求。"
    }
  ],
  "contentLength": "适中",
  "draftingUnit": ""
}
```

### 用户提示词模板

```text
当前任务：AI 仿写的“仿写要求辅助生成”
新主题：{{title}}
参考样稿文体：{{copyAnalysis.docType}}
参考样稿主题词：{{copyAnalysis.keywords}}
参考样稿行文方向：{{copyAnalysis.directions}}
参考样稿语气特征：{{copyAnalysis.tones}}
目标篇幅：{{contentLength}}
拟文单位：{{draftingUnit}}
参考样稿的已确认结构解析：
{{copyAnalysis.structureItems}}

请生成可直接回填到“仿写要求”的一段建议。必须基于以上最终确认的结构解析：说明要保留哪些结构层级、每一层的写作功能/展开方式、总体行文方向和语气特征；围绕新主题重新组织内容。只继承结构和表达方法，不得要求复制样稿中的具体句子、单位、人物、数据、案例或事实。若行文方向或语气特征为空，不要补造。不要输出仿写正文。
```

### 预期回填示例

```text
参照通知类文稿的三层结构展开：首段说明开展检查的背景和总体要求，中段按重点任务分条写明检查内容与推进方式，末段落到责任落实和督导反馈；保持下行、正式稳妥的工作化口径，围绕二季度安全生产检查重新组织内容，不沿用样稿中的具体事实和表述。
```

## 9. 研发拼接示例

```ts
const systemPrompt = REQUIREMENT_ASSISTANT_SYSTEM_PROMPT;
const userPrompt = buildRequirementAssistantPrompt({
  mode,
  title,
  documentCategory,
  sceneName,
  wordCount,
  draftingUnit,
  sourceContent,
  copyAnalysis,
});

const result = await llm.generate({
  systemPrompt,
  userPrompt,
  temperature: 0.25,
  maxTokens: mode === 'AI仿写' ? 480 : 320,
});

setRequirement(result.text.trim().slice(0, mode === 'AI仿写' ? 260 : 180));
```

不要把参考素材、知识库文件或后续生成结果带入此任务：它们在点击「AI生成」时尚未选择，且与“补全写作要求”的职责无关。
