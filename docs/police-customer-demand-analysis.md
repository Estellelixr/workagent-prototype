# 公安客户智能公文需求分析文档

## 1. 结论摘要

从湖北公安、湖北顺义、北京人口三批客户反馈看，客户核心诉求并不是泛化的 Agent 平台，而是面向公安政务场景的智能公文生产工具。

产品应优先围绕“公文写作、校对、润色、排版、模板复用、知识库管理、数据替换、领导风格适配”形成闭环。对外表达建议弱化“智能体专家”概念，强化“公安场景智能公文工作台”定位。

建议产品定位：

> 面向公安政务办公场景的智能公文工作台，以公文写作、校对、润色、排版为基础能力，通过单位知识库、模板库、领导风格库和业务数据接入，帮助指挥中心、综合内勤、督查督办等高频写作岗位提升材料生产效率和规范性。

## 3. 当前产品可直接承接的能力

| 当前能力 | 可承接客户需求 | 说明 |
|---|---|---|
| AI 写作：生成全文、生成大纲、大纲成文、继续写、生成结语 | 通知、总结、汇报、通报、材料初稿 | 可作为公安公文写作主入口 |
| AI 仿写 | 优秀材料复用、领导风格参考、固定结构复用 | 适合“按照已有范文写类似材料” |
| AI 润色 | 文件润色、减少口语化、提升正式表达 | 指挥中心和内勤岗位接受度高 |
| 智能校对 | 错别字、基础错误、规范检查 | 可切入文件审核压力大的部门 |
| 智能排版 | 公文格式规范、文稿成稿处理 | 需继续加强红头模板和标准版式 |
| 知识库 | 个人材料、部门材料、公共素材管理 | 可承接部门共享和个人保密诉求 |
| 参考素材参与生成 | 使用本地文件、知识库文件辅助生成 | 可承接优秀材料、标准公文、法规材料 |
| 后台提示词和模型配置 | 按业务节点配置不同提示词和模型 | 适合后续沉淀公安场景提示词 |
| WebOffice 编辑闭环 | 生成后编辑、排版、保存文稿 | 贴近公文工作流 |

## 5. 有产品化价值的方向

### 5.1 P0：应作为近期产品主线

| 方向 | 产品价值 | 原因 |
|---|---|---|
| AI 校对、润色、排版 | 快速见效、客户认可度高 | 三家客户均明确认可基础文稿处理能力 |
| 公安公文场景库 | 强化行业定位 | 可降低客户使用门槛，避免泛化写作 |
| 模板库 | 与公安公文强绑定 | 固定模板、红头模板、优秀材料是客户高频诉求 |
| 重点专项工作汇报 | 高价值场景 | 北京人口明确提出耗时、重要、领导关注 |
| 内勤和政工类制式文档 | 满足度高 | 格式化、程序化强，适合 AI 辅助 |

### 5.2 P1：应作为增强能力规划

| 方向 | 产品价值 | 原因 |
|---|---|---|
| 数据替换和 Excel/业务数据接入 | 高价值但依赖系统 | 能形成“模板 + 数据 + 文稿”的差异化能力 |
| 多材料融合 | 减负明显 | 可解决专班从多部门材料中找内容的痛点 |
| 领导风格适配 | 有销售吸引力 | 需样本、权限和治理机制，不能过度承诺 |
| 法规知识库检索 | 公安行业适配 | 可加强专业可信感 |
| 拆稿/分发生成 | 垂直场景强 | 适合通报、区域材料拆分 |

### 5.3 P2/P3：暂不建议作为当前主线

| 方向 | 原因 |
|---|---|
| AI PPT | 有需求，但与公文主线相比优先级略低 |
| 视频剪辑、党建学习 | 需求发散，容易稀释产品定位 |
| 手机端签批、无纸化办公 | 更偏 OA/流程系统，依赖网络和审批集成 |
| 派出所笔录制作 | 技术和业务复杂度高，需独立专项评估 |

## 6. 项目定制化开发边界

以下内容建议明确归为“项目定制”或“交付方案”，不要直接包装成标准产品承诺：

| 定制事项 | 原因 |
|---|---|
| 适配顺义现有云平台、RAM 架构、T4/Atlas 算力 | 与客户环境强绑定，需要现场核查 |
| 对接公安业务系统、数据平台、Excel 数据源 | 数据结构、权限、接口各单位不同 |
| 雪亮工程项目集成 | 项目边界、预算、平台方、网络环境复杂 |
| 手机端警务无线网签批 | 涉及公安网和警务无线网隔离 |
| 人口总队现场 FDE 定制开发 | 明确属于试点项目现场交付 |
| 特定领导风格深度训练 | 样本、权限、脱敏、审计要求不同 |
| 派出所笔录制作 | 属于独立业务系统能力，不宜混入当前 MVP |

## 7. 建议产品路线

| 阶段 | 建设重点 | 目标 |
|---|---|---|
| 第一阶段：快速落地 | AI 写作、润色、校对、排版、知识库、模板库基础版 | 先让指挥中心、综合内勤、督查督办能用起来 |
| 第二阶段：场景深化 | 专项汇报、通报、总结、内勤政工材料、公安场景提示词 | 从通用公文工具升级为公安公文工作台 |
| 第三阶段：数据增强 | Excel 数据替换、模板字段映射、周报月报自动生成 | 解决固定模板材料的重复劳动 |
| 第四阶段：组织协同 | 部门知识库、领导风格库、优秀材料库、权限治理 | 支持单位级素材沉淀和复用 |
| 第五阶段：项目拓展 | 私有化部署、系统对接、移动端、专项定制 | 支撑大项目和行业化复制 |

## 8. 推荐对外话术

### 8.1 产品定位话术

我们不是做一个泛化的 Agent 平台，而是面向公安政务场景，提供一套可私有化部署的智能公文工作台。产品以公文写作、润色、校对、排版为基础能力，结合单位知识库、模板库、领导风格库和业务数据接入，帮助指挥中心、综合内勤、督查督办等高频写作岗位降低文稿处理压力，提高材料质量和流转效率。

### 8.2 面向湖北公安

建议优先以指挥中心文件审核和文稿流转为切入点，通过 AI 校对、润色、排版减少基础错误，提高周静队长所在文件收发归口的处理效率。后续可导入公安系统标准公文、红头模板、优秀材料和领导常用材料，逐步形成部门级共享知识库和领导风格适配能力。

### 8.3 面向湖北顺义

建议先围绕校对、排版、润色和总结类材料生成做试用，验证基层单位实际减负效果。同时结合顺义现有云平台资源，设计纯软件私有化部署方案。法律法规知识库、Excel 重点人名单查询、AI PPT 等需求可作为二期扩展能力规划。

### 8.4 面向北京人口

建议重点落地“重点专项工作汇报、内勤和政工类制式文档、多支队材料汇总提取”三类场景。通过固定模板、数据替换、多材料融合和领导风格适配，解决专项汇报、周报月报、通报拆分等高频耗时工作。
